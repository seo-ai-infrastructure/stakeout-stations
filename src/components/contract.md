# Integration contract

Final extensions: template creation also accepts `template_type: 1 | 2` (official/custom). Device PATCH supports `action: 'environment_settings'` with `environment_refresh_enabled`. Manual environment refresh sets `force_refresh` in the server-created job and advances the location revision. Identity metadata is optional on `Device`; encrypted immutable baselines use service-only `get_device_identity` / `lock_device_identity` RPCs. Route arrival uses a version-fenced `complete_route` RPC to update S2 and create a new Environment Sync job atomically. Worker telemetry and control queues are separate; compatible GPS requests batch up to 20 images.

Next.js root project, src/app, src/components, src/lib; worker in worker/src. Shared types in src/shared/types.ts. All database rows use snake_case.

UI: GET /api/dashboard returns DashboardData. No configured environment returns a clearly labeled demo with UI-owned demo data; no real operations allowed in demo. If configured but signed out, return 401, UI offers /login. POST /api/organizations {name}. POST /api/keys {provider,key_alias,secret} where secret is DuoPlus API string or WiGLE JSON string {apiName,apiToken}. DELETE /api/keys/[id]. POST /api/keys/[id]/test queues device_sync for DuoPlus. WiGLE Test returns 409 and directs operators to a station Environment Sync; it does not issue a standalone lookup. POST /api/devices {station_code,duoplus_device_id,lat,lng,mode}. PATCH /api/devices/[id] {action:'park'|'pause'|'resume'|'relocate'|'navigate',lat?,lng?,route?,route_speed_mps?}. POST /api/devices/[id]/environment-sync. POST /api/templates {name,duoplus_template_id,variables}. POST /api/jobs {kind,device_id?,payload?}. PATCH /api/organizations/[id] {capacity,duoplus_interval_ms?,telemetry_interval_ms?}. All API mutation schemas validate and auth+org authorize. Browser private Realtime channel org:<org_id>:telemetry, event tick, payload TelemetryTick. Database controls use Postgres Changes scoped by org.

DB: public organizations, org_members, api_keys (metadata only), devices (station and anchor included), telemetry_ticks, jobs (durable outbox), job_attempts, rpa_templates, environment_snapshots. Secrets use Supabase Vault, reference isolated in private schema and service-only RPC. Service RPC get_credential(p_org_id,p_key_id) returns decrypted secret string. Store RPC store_credential(p_org_id,p_provider,p_alias,p_secret) callable user session with admin authorization; delete RPC delete_credential(p_key_id). Worker reads service-only get_credential. Worker checks org_id on every row lookup and updates with org+id+version filters. No raw credentials in queue/logs.

Jobs payload env sync contains environment_version and target coordinates from DB only; derive tenant/device/key fresh, reject stale revision. Outbox jobs picked by supervisor, use row id as BullMQ job id (no colons). Environment cache version lock. Environment sync separate queue, WiGLE never in tick loop. Default rate limit tenant 1200ms, do not multiply by number of keys automatically. Capacity default 3 adjustable, counts provider-on devices; worker must verify external inventory for live power actions. Simulation must be labeled, never imply device measured accuracy or current WiGLE signal.

Vercel env: NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY; optional SUPABASE_SECRET_KEY for backend if unavoidable, prefer user-scoped Vault-store functions. Worker: SUPABASE_URL, SUPABASE_SECRET_KEY, REDIS_URL, ENGINE_ENABLED=false default, PORT=8080. No fabricated credentials, telemetry, AP or carrier defaults in real mode. Demo separate clearly marked.
